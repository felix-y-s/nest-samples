# 이벤트 스트림 개념 가이드

## 개요

**"한 Aggregate의 이벤트는 한 스트림에만 저장된다"**

이것은 이벤트 소싱(Event Sourcing)의 가장 기본적이면서도 중요한 원칙입니다. 이 문서에서는 이벤트 스트림의 개념과 왜 이 원칙이 중요한지 설명합니다.

## 이벤트 스트림이란?

**이벤트 스트림(Event Stream)**은 하나의 Aggregate 인스턴스에서 발생한 모든 이벤트들의 시간순 목록입니다.

데이터베이스로 비유하면:
- **전통적 DB**: 한 행(row)에 현재 상태만 저장
- **이벤트 스트림**: 한 Aggregate의 전체 히스토리(이벤트 목록)를 저장

### EventStore 내부 구조

```typescript
// Map<aggregateId, Event[]>
{
  "order-123": [
    OrderCreatedEvent,
    OrderCompletedEvent
  ],
  "payment-456": [
    PaymentAttemptedEvent,
    PaymentSuccessedEvent
  ]
}
```

각 `aggregateId`가 하나의 스트림을 식별하고, 그 스트림에는 해당 Aggregate의 이벤트만 저장됩니다.

## 왜 각 Aggregate가 자신만의 스트림을 가져야 하나?

### 1️⃣ Aggregate 복원 (Event Replay)

Aggregate를 복원할 때는 **해당 Aggregate의 이벤트만** 순서대로 재생해야 합니다:

```typescript
// ✅ 올바른 복원 방법
async findById(paymentId: string): Promise<PaymentAggregate> {
  // 1. Payment 스트림에서 Payment 이벤트만 가져오기
  const events = this.eventStore.getEvents(paymentId);  // "payment-456"
  // events = [PaymentAttemptedEvent, PaymentSuccessedEvent]

  // 2. 새 Aggregate 인스턴스 생성
  const payment = new PaymentAggregate(paymentId);

  // 3. 이벤트를 순서대로 재생하여 상태 복원
  for (const event of events) {
    payment.onPaymentAttemptedEvent(event);  // 내부 상태 업데이트
  }

  return payment;  // 완전히 복원된 Aggregate
}
```

**핵심 포인트:**
- Payment Aggregate를 복원하려면 Payment 이벤트만 필요
- Order 이벤트나 다른 Aggregate의 이벤트는 불필요
- 순서가 중요: 이벤트는 발생한 순서대로 재생되어야 함

### 2️⃣ 도메인 경계 유지

각 Aggregate는 독립적인 트랜잭션 경계입니다:

```typescript
// Order Aggregate는 Order 이벤트만 처리
class OrderAggregate extends AggregateRoot {
  onOrderCreatedEvent(event: OrderCreatedEvent) {
    this.orderId = event.orderId;
    this.status = OrderStatus.CREATED;
  }

  onOrderCompletedEvent(event: OrderCompletedEvent) {
    this.status = OrderStatus.COMPLETED;
  }
}

// Payment Aggregate는 Payment 이벤트만 처리
class PaymentAggregate extends AggregateRoot {
  constructor(paymentId: string) {
    super();
    this.paymentId = paymentId;  // 생성자에서 ID 설정
  }

  onPaymentAttemptedEvent(event: PaymentAttemptedEvent) {
    // paymentId는 생성자에서 이미 설정됨 (재설정 불필요)
    this.orderId = event.orderId;
    this.userId = event.userId;
    this.amount = event.amount;
    this.status = PaymentStatus.PROCESSING;
  }

  onPaymentSuccessedEvent(event: PaymentSuccessedEvent) {
    // 성공 관련 속성만 설정
    this.transactionId = event.transactionId;
    this.status = PaymentStatus.SUCCEEDED;
    // orderId, userId, amount는 이미 설정됨 (재설정 안 함)
  }
}
```

## 잘못된 스트림 구성의 문제점

### ❌ 현재 버그 상황

```typescript
// EventStore 내부 (잘못된 구조)
{
  "order-123": [
    OrderCreatedEvent,           // ✅ Order 이벤트
    PaymentAttemptedEvent,       // ❌ Payment 이벤트가 Order 스트림에!
    PaymentSuccessedEvent,       // ❌ Payment 이벤트가 Order 스트림에!
    OrderCompletedEvent          // ✅ Order 이벤트
  ],
  "payment-456": []  // ❌ Payment 스트림이 비어있음!
}
```

### 발생하는 문제들

#### 문제 1: Payment Aggregate 복원 불가능
```typescript
// Payment Aggregate 복원 시도
const events = this.eventStore.getEvents("payment-456");
// events = []  ❌ 비어있음!

const payment = new PaymentAggregate("payment-456");
// 이벤트가 없어서 초기 상태 그대로 → 복원 실패!
```

#### 문제 2: Order Aggregate 복원 시 타입 에러
```typescript
// Order Aggregate 복원 시도
const events = this.eventStore.getEvents("order-123");
// events = [OrderCreatedEvent, PaymentAttemptedEvent, PaymentSuccessedEvent, OrderCompletedEvent]

const order = new OrderAggregate("order-123");
for (const event of events) {
  if (event instanceof OrderCreatedEvent) {
    order.onOrderCreatedEvent(event);  // ✅
  } else if (event instanceof PaymentAttemptedEvent) {
    // ❌ OrderAggregate는 PaymentAttemptedEvent를 처리할 수 없음!
    // 타입 에러 또는 무시됨
  }
}
```

## 구체적인 예시 비교

### ✅ 올바른 구조

```typescript
{
  // Order Aggregate 스트림 (Order 이벤트만)
  "order-123": [
    OrderCreatedEvent {
      orderId: "order-123",
      userId: "user-1",
      amount: 50000
    },
    OrderCompletedEvent {
      orderId: "order-123"
    }
  ],

  // Payment Aggregate 스트림 (Payment 이벤트만)
  "payment-456": [
    PaymentAttemptedEvent {
      paymentId: "payment-456",
      orderId: "order-123",  // 연관 정보
      amount: 50000
    },
    PaymentSuccessedEvent {
      paymentId: "payment-456",
      orderId: "order-123",  // 연관 정보
      transactionId: "pg-789"
    }
  ]
}
```

**복원 결과:**
- ✅ `OrderRepository.findById("order-123")` → Order 이벤트 2개로 Order 복원 성공
- ✅ `PaymentRepository.findById("payment-456")` → Payment 이벤트 2개로 Payment 복원 성공

**도메인 간 연관:**
- Payment 이벤트가 `orderId`를 속성으로 가지고 있어서 어떤 Order와 연관되는지 알 수 있음
- 하지만 이벤트는 각자의 스트림에 저장됨
- 도메인 간 통신은 이벤트 핸들러를 통해 이루어짐

### ❌ 현재 버그 상황

```typescript
{
  // Order 스트림에 Payment 이벤트까지 섞임
  "order-123": [
    OrderCreatedEvent { orderId: "order-123" },
    PaymentAttemptedEvent {
      paymentId: "payment-456",
      orderId: "order-123"  // orderId 때문에 Order 스트림에 저장됨
    },
    PaymentSuccessedEvent {
      paymentId: "payment-456",
      orderId: "order-123"  // orderId 때문에 Order 스트림에 저장됨
    },
    OrderCompletedEvent { orderId: "order-123" }
  ],

  // Payment 스트림은 비어있음
  "payment-456": []  // ❌ Payment를 복원할 수 없음
}
```

**복원 결과:**
- ❌ `OrderRepository.findById("order-123")` → Payment 이벤트 처리 불가로 에러 발생
- ❌ `PaymentRepository.findById("payment-456")` → 이벤트가 없어서 복원 불가능

## 왜 이런 버그가 발생했나?

### extractAggregateId의 잘못된 우선순위

```typescript
// 현재 EventStoreService 코드
private extractAggregateId(event: any): string | null {
  if (event.orderId) return event.orderId;  // 1순위 ❌
  if (event.userId) return event.userId;    // 2순위
  if (event.id) return event.id;            // 3순위
  if (event.aggregateId) return event.aggregateId;  // 4순위 ❌
}
```

### 문제 발생 과정

```typescript
// PaymentAttemptedEvent 발행 시
const event = new PaymentAttemptedEvent(
  "payment-456",  // paymentId
  "order-123",    // orderId ← 문제의 속성
  "user-1",
  50000,
  new Date()
);

// EventStore에 저장 시도
this.eventBus.publish(event);

// extractAggregateId 실행
// event.orderId = "order-123" 발견 → "order-123"를 aggregateId로 사용
// → "order-123" 스트림에 저장 (Order 스트림에 Payment 이벤트 저장!)
```

### 올바른 우선순위

```typescript
// 해결 방안: aggregateId를 최우선으로
private extractAggregateId(event: any): string | null {
  if (event.aggregateId) return event.aggregateId;  // 1순위 ✅
  if (event.paymentId) return event.paymentId;      // 2순위
  if (event.orderId) return event.orderId;          // 3순위
  if (event.userId) return event.userId;            // 4순위
  if (event.id) return event.id;                    // 5순위
  return null;
}
```

## 이벤트 속성에 다른 Aggregate ID가 있어도 되나?

**네, 문제없습니다!** 중요한 것은 **어느 스트림에 저장되는가**입니다.

### 올바른 예시

```typescript
// PaymentAttemptedEvent
class PaymentAttemptedEvent {
  constructor(
    public readonly paymentId: string,      // 이 이벤트의 Aggregate ID
    public readonly orderId: string,        // 연관된 Order (참조용)
    public readonly userId: string,         // 연관된 User (참조용)
    public readonly amount: number,
    public readonly attemptedAt: Date,
  ) {}
}

// 저장 시
const event = new PaymentAttemptedEvent(
  "payment-456",  // paymentId → 이것이 aggregateId로 사용되어야 함
  "order-123",    // orderId → 단순 참조 정보
  "user-1",       // userId → 단순 참조 정보
  50000,
  new Date()
);

// "payment-456" 스트림에 저장 ✅
```

**핵심 원칙:**
- `paymentId`는 이 이벤트의 주인(Payment Aggregate)을 나타냄
- `orderId`, `userId`는 단순히 연관 정보 (참조)
- 이벤트는 **주인의 스트림**(`paymentId`)에 저장되어야 함

## 정리

### "한 Aggregate의 이벤트는 한 스트림에만 저장된다"의 의미

1. **Order Aggregate 인스턴스 "order-123"**
   - Order 이벤트들만 "order-123" 스트림에 저장
   - OrderCreatedEvent, OrderCompletedEvent, OrderCancelledEvent 등

2. **Payment Aggregate 인스턴스 "payment-456"**
   - Payment 이벤트들만 "payment-456" 스트림에 저장
   - PaymentAttemptedEvent, PaymentSuccessedEvent, PaymentFailedEvent 등

3. **절대로 섞이면 안됨**
   - 각 Aggregate는 자신의 이벤트로만 복원 가능
   - 다른 Aggregate의 이벤트가 섞이면 복원 실패 또는 타입 에러

### 도메인 간 연관은 어떻게?

이벤트 속성에 다른 Aggregate ID를 포함해도 됩니다:

```typescript
PaymentAttemptedEvent {
  paymentId: "payment-456",  // 주인 (이 스트림에 저장)
  orderId: "order-123",      // 참조 (연관 정보)
  amount: 50000
}
```

도메인 간 통신은 **이벤트 핸들러**를 통해:

```typescript
@EventsHandler(PaymentSuccessedEvent)
export class PaymentSuccessedHandler {
  async handle(event: PaymentSuccessedEvent) {
    // Payment 도메인의 이벤트를 Order 도메인에서 받아서 처리
    const order = await this.orderRepository.findById(event.orderId);
    order.complete();  // Order 상태 업데이트
    order.commit();    // OrderCompletedEvent 발행
  }
}
```

### 현재 프로젝트의 문제

- `extractAggregateId`가 `orderId`를 최우선으로 처리
- Payment 이벤트가 Order 스트림에 저장됨
- Payment Aggregate 복원 불가능

**해결 필요:**
- EventStore 로직 수정 (우선순위 변경 또는 명시적 aggregateId 사용)
- 상세한 해결 방안은 [Order-Payment 통합 설계 문서](./order-payment-integration-design.md) 참고
