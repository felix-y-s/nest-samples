# CorrelationId로 비즈니스 트랜잭션 조회 가이드

## 개요

이벤트 소싱에서 **aggregateId**는 Aggregate 인스턴스를 구분하는 ID입니다. 하지만 하나의 **비즈니스 트랜잭션**(예: 주문 생성 → 결제 → 주문 완료)은 여러 Aggregate에 걸쳐 발생합니다.

이런 비즈니스 플로우를 추적하려면 **correlationId**(상관관계 ID)가 필요합니다.

## AggregateId vs CorrelationId

### AggregateId (필수)

- **목적**: Aggregate 인스턴스 구분 (이벤트 스트림 식별자)
- **범위**: 하나의 Aggregate 인스턴스
- **예시**:
  - Order Aggregate "order-456"의 aggregateId = "order-456"
  - Payment Aggregate "payment-123"의 aggregateId = "payment-123"

```typescript
EventStore = {
  "order-456": [OrderCreatedEvent, OrderCompletedEvent],
  "payment-123": [PaymentAttemptedEvent, PaymentSuccessedEvent]
}
```

### CorrelationId (선택사항)

- **목적**: 비즈니스 트랜잭션 추적 (여러 Aggregate 연결)
- **범위**: 하나의 비즈니스 플로우
- **예시**:
  - "order-flow-order-456" = 주문 생성부터 완료까지 전체 플로우

```typescript
// CorrelationId로 그룹화
"order-flow-order-456": [
  OrderCreatedEvent { aggregateId: "order-456" },
  PaymentAttemptedEvent { aggregateId: "payment-123" },
  PaymentSuccessedEvent { aggregateId: "payment-123" },
  OrderCompletedEvent { aggregateId: "order-456" }
]
```

## CorrelationId 조회 구현 방법

### 방법 1: 보조 인덱스 추가 (간단)

EventStore에 correlationId별 인덱스를 추가하는 방법입니다.

#### 1.1 EventStore 수정

```typescript
@Injectable()
export class EventStoreService implements OnModuleInit {
  // 기본 스토어: Aggregate별 이벤트
  private readonly eventStore = new Map<string, IEvent[]>();

  // ✅ 보조 인덱스: CorrelationId별 이벤트
  private readonly correlationIndex = new Map<string, IEvent[]>();

  constructor(private readonly eventBus: EventBus) {}

  onModuleInit() {
    this.eventBus.subscribe((event: IEvent) => {
      this.saveEvent(event);
    });
  }

  private saveEvent(event: IEvent) {
    // 1. Aggregate 스트림에 저장
    const aggregateId = this.extractAggregateId(event);
    if (aggregateId) {
      const events = this.eventStore.get(aggregateId) || [];
      events.push(event);
      this.eventStore.set(aggregateId, events);
    }

    // 2. ✅ Correlation 인덱스에도 저장
    const correlationId = this.extractCorrelationId(event);
    if (correlationId) {
      const correlatedEvents = this.correlationIndex.get(correlationId) || [];
      correlatedEvents.push(event);
      this.correlationIndex.set(correlationId, correlatedEvents);

      console.log(`📌 [Correlation Index] ${correlationId}:`, {
        eventType: event.constructor.name,
        totalEvents: correlatedEvents.length,
      });
    }
  }

  private extractAggregateId(event: any): string | null {
    if (event.aggregateId) return event.aggregateId;
    if (event.paymentId) return event.paymentId;
    if (event.orderId) return event.orderId;
    return null;
  }

  private extractCorrelationId(event: any): string | null {
    // correlationId 속성이 있는 이벤트만 인덱싱
    return event.correlationId || null;
  }

  // Aggregate별 조회 (기존)
  getEvents(aggregateId: string): IEvent[] {
    return this.eventStore.get(aggregateId) || [];
  }

  // ✅ CorrelationId별 조회 (신규)
  getEventsByCorrelation(correlationId: string): IEvent[] {
    return this.correlationIndex.get(correlationId) || [];
  }

  // ✅ CorrelationId별 시간순 정렬 조회
  getEventsByCorrelationSorted(correlationId: string): IEvent[] {
    const events = this.correlationIndex.get(correlationId) || [];
    return events.sort((a: any, b: any) => {
      const timeA = a.occurredAt || a.createdAt || a.attemptedAt || new Date(0);
      const timeB = b.occurredAt || b.createdAt || b.attemptedAt || new Date(0);
      return timeA.getTime() - timeB.getTime();
    });
  }

  // ✅ 전체 Correlation ID 목록 조회
  getAllCorrelationIds(): string[] {
    return Array.from(this.correlationIndex.keys());
  }
}
```

### 방법 2: Read Model 구성 (CQRS 권장) ⭐

더 확장 가능한 방법은 **별도의 Read Model**을 만드는 것입니다.

#### 2.1 OrderFlowReadModel 정의

```typescript
// Order 플로우 상태를 저장하는 Read Model
export interface OrderFlowReadModel {
  correlationId: string;
  orderId: string;
  userId: string;
  amount: number;
  status: 'CREATED' | 'PAYMENT_PROCESSING' | 'PAYMENT_COMPLETED' | 'COMPLETED' | 'FAILED';
  events: Array<{
    type: string;
    occurredAt: Date;
    data: any;
  }>;
  createdAt: Date;
  updatedAt: Date;
}

// Read Model Repository
@Injectable()
export class OrderFlowReadModelRepository {
  // 메모리 기반 (실제로는 MongoDB, PostgreSQL 등 사용)
  private readonly flows = new Map<string, OrderFlowReadModel>();

  save(flow: OrderFlowReadModel): void {
    this.flows.set(flow.correlationId, flow);
  }

  findByCorrelationId(correlationId: string): OrderFlowReadModel | null {
    return this.flows.get(correlationId) || null;
  }

  findByOrderId(orderId: string): OrderFlowReadModel | null {
    const correlationId = `order-flow-${orderId}`;
    return this.findByCorrelationId(correlationId);
  }

  findAll(): OrderFlowReadModel[] {
    return Array.from(this.flows.values());
  }

  findByStatus(status: string): OrderFlowReadModel[] {
    return Array.from(this.flows.values())
      .filter(flow => flow.status === status);
  }

  // 복잡한 쿼리 예시
  findCompletedFlowsInPeriod(startDate: Date, endDate: Date): OrderFlowReadModel[] {
    return Array.from(this.flows.values())
      .filter(flow =>
        flow.status === 'COMPLETED' &&
        flow.updatedAt >= startDate &&
        flow.updatedAt <= endDate
      );
  }
}
```

#### 2.2 이벤트 핸들러로 Read Model 업데이트

```typescript
// OrderCreatedEvent 핸들러
@EventsHandler(OrderCreatedEvent)
export class OrderCreatedReadModelHandler {
  constructor(
    private readonly flowRepository: OrderFlowReadModelRepository,
  ) {}

  async handle(event: OrderCreatedEvent) {
    const flow: OrderFlowReadModel = {
      correlationId: event.correlationId,
      orderId: event.orderId,
      userId: event.userId,
      amount: event.amount,
      status: 'CREATED',
      events: [{
        type: 'OrderCreated',
        occurredAt: event.createdAt,
        data: event,
      }],
      createdAt: event.createdAt,
      updatedAt: event.createdAt,
    };

    this.flowRepository.save(flow);

    console.log(`✅ [Read Model] OrderFlow 생성:`, {
      correlationId: flow.correlationId,
      status: flow.status,
    });
  }
}

// PaymentAttemptedEvent 핸들러
@EventsHandler(PaymentAttemptedEvent)
export class PaymentAttemptedReadModelHandler {
  constructor(
    private readonly flowRepository: OrderFlowReadModelRepository,
  ) {}

  async handle(event: PaymentAttemptedEvent) {
    const flow = this.flowRepository.findByCorrelationId(event.correlationId);
    if (!flow) {
      console.warn(`⚠️ OrderFlow not found: ${event.correlationId}`);
      return;
    }

    // Read Model 업데이트
    flow.status = 'PAYMENT_PROCESSING';
    flow.events.push({
      type: 'PaymentAttempted',
      occurredAt: event.attemptedAt,
      data: event,
    });
    flow.updatedAt = event.attemptedAt;

    this.flowRepository.save(flow);

    console.log(`✅ [Read Model] OrderFlow 업데이트:`, {
      correlationId: flow.correlationId,
      status: flow.status,
    });
  }
}

// PaymentSuccessedEvent 핸들러
@EventsHandler(PaymentSuccessedEvent)
export class PaymentSuccessedReadModelHandler {
  constructor(
    private readonly flowRepository: OrderFlowReadModelRepository,
  ) {}

  async handle(event: PaymentSuccessedEvent) {
    const flow = this.flowRepository.findByCorrelationId(event.correlationId);
    if (!flow) return;

    flow.status = 'PAYMENT_COMPLETED';

      type: 'PaymentSuccessed',

    this.flowRepository.save(flow);
  }

@EventsHandler(OrderCompletedEvent)

  constructor(
    private readonly flowRepository: OrderFlowReadModelRepository,
  ) {}

  async handle(event: OrderCompletedEvent) {
    const flow = this.flowRepository.findByCorrelationId(event.correlationId);
    if (!flow) return;

    flow.status = 'COMPLETED';
```

#### 2.3 API Controller 구현

```typescript
@Controller('order-flows')
export class OrderFlowController {
  constructor(
    private readonly flowRepository: OrderFlowReadModelRepository,
  ) {}

  // 특정 주문의 플로우 조회
  @Get(':orderId')
  async getOrderFlow(@Param('orderId') orderId: string) {
    const flow = this.flowRepository.findByOrderId(orderId);

    if (!flow) {
      throw new NotFoundException(`OrderFlow not found for orderId: ${orderId}`);
    }

    return {
      orderId: flow.orderId,
      status: flow.status,
      amount: flow.amount,
      timeline: flow.events.map(e => ({
        step: e.type,
        time: e.occurredAt,
      })),
      createdAt: flow.createdAt,
      updatedAt: flow.updatedAt,
    };
  }

  // 모든 진행중인 플로우 조회
  @Get('status/processing')
  async getProcessingFlows() {
    const flows = this.flowRepository.findByStatus('PAYMENT_PROCESSING');

    return flows.map(flow => ({
      orderId: flow.orderId,
      status: flow.status,
      amount: flow.amount,
      createdAt: flow.createdAt,
    }));
  }

  // 완료된 플로우 통계
  @Get('statistics/completed')
  async getCompletedStatistics(
    @Query('startDate') startDate: string,
    @Query('endDate') endDate: string,
  ) {
    const start = new Date(startDate);
    const end = new Date(endDate);

    const flows = this.flowRepository.findCompletedFlowsInPeriod(start, end);

    const totalAmount = flows.reduce((sum, flow) => sum + flow.amount, 0);

    return {
      totalOrders: flows.length,
      totalAmount,
      averageAmount: totalAmount / flows.length,
      period: { startDate: start, endDate: end },
    };
  }
}
```

### 방법 3: 전체 스캔 (비추천)

```typescript
// ❌ 비효율적 - 운영 환경에서는 사용하지 마세요
getEventsByCorrelationSlow(correlationId: string): IEvent[] {
  const result: IEvent[] = [];

  // 모든 Aggregate 스트림을 순회 (O(n))
  for (const [aggregateId, events] of this.eventStore.entries()) {
    for (const event of events) {
      if ((event as any).correlationId === correlationId) {
        result.push(event);
      }
    }
  }

  // 시간순 정렬
  return result.sort((a: any, b: any) => {
    const timeA = a.occurredAt || a.createdAt || new Date(0);
    const timeB = b.occurredAt || b.createdAt || new Date(0);
    return timeA.getTime() - timeB.getTime();
  });
}
```

**장점**: 구현 매우 간단

**단점**:
- 성능 최악 (O(n) - 모든 이벤트 스캔)
- 운영 환경 사용 불가
- 이벤트가 많아질수록 느려짐

**사용 시나리오**: 디버깅, 개발 환경에서만

## 비교 및 추천

| 방법 | 복잡도 | 성능 | 쿼리 기능 | 메모리 | 추천 시나리오 |
|------|--------|------|-----------|--------|--------------|
| **보조 인덱스** | 낮음 | O(1) | 단순 조회 | 중간 | 프로토타입, 간단한 조회 |
| **Read Model** ⭐ | 높음 | O(1) + DB | 복잡한 쿼리 | 낮음 | 운영 환경, 복잡한 비즈니스 로직 |
| **전체 스캔** | 매우 낮음 | O(n) | 단순 조회 | 낮음 | 디버깅, 개발 환경 |

## 추천 구현 순서

### Phase 1: 보조 인덱스로 시작

1. BaseEvent에 `correlationId?: string` 추가
2. EventStore에 `correlationIndex` Map 추가
3. `getEventsByCorrelation()` 메서드 구현
4. 주요 이벤트에 correlationId 설정

**예상 소요 시간**: 1-2시간

### Phase 2: Read Model로 진화

1. OrderFlowReadModel 인터페이스 정의
2. OrderFlowReadModelRepository 구현
3. 각 이벤트에 대한 Read Model 핸들러 작성
4. API Controller에서 Read Model 조회

**예상 소요 시간**: 4-8시간

### Phase 3: 고급 기능 추가

1. 복잡한 쿼리 (통계, 필터링, 집계)
2. 실시간 알림 (WebSocket)
3. 대시보드 UI
4. 성능 최적화 (캐싱, 인덱싱)

```typescript
// 모든 도메인 이벤트에 correlationId 전파
class OrderAggregate {
  constructor(
    private orderId: string,
    private correlationId?: string,  // ✅ Aggregate에서 관리
  ) {}

  create(userId: string, amount: number) {
    // correlationId 생성 (최초 1회)
    if (!this.correlationId) {
      this.correlationId = `order-flow-${this.orderId}`;
    }

    this.apply(new OrderCreatedEvent(
      this.orderId,
      userId,
      amount,
      new Date(),
      this.correlationId,  // ✅ 전파
    ));
  }
}
```
