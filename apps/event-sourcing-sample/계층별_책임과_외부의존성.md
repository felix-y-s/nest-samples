# 계층별 책임과 외부 의존성 관리

이벤트 소싱 아키텍처에서 각 계층의 역할과 외부 의존성 관리 원칙을 상세히 설명합니다.

  **핵심**

  1. 이벤트 소싱의 3가지 핵심 원칙
    - 이벤트 불변성: 과거는 바꿀 수 없다, 보상 이벤트로 대응
    - 이벤트 완전성: 모든 정보를 이벤트에 포함 (외부 참조 금지)
    - 멱등성: Aggregate와 EventStore는 필수, Event Handler는 권장
  2. 계층 간 책임 분리
    - Command Handler: 외부 데이터 조회 (예: ProductService, UserService)
    - Aggregate: 순수 도메인 로직 (외부 의존성 절대 금지)
    - Event Handler: 외부 시스템 통합 (DB, API, 이메일 등)
  3. 실무 핵심: 예방 > 보상
    - 예방: Command Handler에서 재고 예약 (80% 문제 방지)
    - 보상: Event Handler 실패 시 취소 Command (15% 처리)
    - DLQ: 영구 실패는 수동 개입 (5% 처리)
  4. Event Handler는 Command를 발행한다
    - Event Handler는 이벤트를 직접 발행할 수 없음
    - Command Bus를 통해 간접 발행
    - 흐름: Event Handler → Command → Aggregate → 보상 이벤트

## 핵심 원칙

### 두 가지 핵심 질문

**Q1: 이벤트 발행 시 Aggregate와 Event Handler는 멱등성이 보장되어야 하고, 외부 데이터(DB 연동 등)는 하면 안 되는가?**

**A1**:
- ✅ **Aggregate**: 멱등성 필수, 외부 의존성 **절대 금지**
- ⚠️ **Event Handler**: 멱등성 권장, 외부 의존성 **허용** (오히려 주요 목적)
- ✅ **EventStore**: 멱등성 필수, DB 연동 **필수**

**Q2: 이벤트 발행 전 (commandBus.execute() 전)에 모든 필요한 외부 데이터를 가져와야 하는가?**

**A2**:
- ✅ **맞습니다!** Command Handler에서 모든 외부 데이터를 조회한 후 Aggregate에 전달해야 합니다.

## 계층별 분석

### 1. Aggregate (순수 도메인 로직)

#### 규칙
- ✅ **멱등성 필수**: 같은 이벤트를 여러 번 재생해도 같은 상태
- ✅ **순수 함수**: 외부 의존성 **절대 금지**
- ✅ **도메인 로직만**: 비즈니스 규칙 검증 + 이벤트 발행

#### 이유
`eventStore.getOrderById()`로 상태 복원 시, 같은 이벤트를 여러 번 재생합니다.
만약 Aggregate에서 DB 호출하면 복원할 때마다 DB 조회 발생! 💥

#### 현재 구현 분석

```typescript
// order.aggregate.ts
export class OrderAggregate extends AggregateRoot {
  createOrder(
    userId: string,
    productId: string,
    productName: string,
    quantity: number,
    price: number,
    discountRate: number,
  ) {
    // ✅ 좋은 예: 순수 검증 로직 (외부 의존성 없음)
    if (quantity <= 0) {
      throw new Error('수량은 0보다 커야 합니다');
    }
    if (price <= 0) {
      throw new Error('가격은 0보다 커야 합니다');
    }
    if (discountRate < 0 || discountRate > 100) {
      throw new Error('할인율은 0-100 사이여야 합니다');
    }

    // ❌ 이런 코드가 있으면 안 됨!
    // const currentPrice = await this.productService.getPrice(productId);
    // await this.database.save(order);

    // ✅ 순수 로직: 이벤트 발행만
    this.apply(
      new OrderCreatedEvent(
        this.orderId,
        userId,
        productId,
        productName,
        quantity,
        price,
        discountRate,
        new Date(),
      ),
    );
  }

  // ✅ 멱등성 보장: 같은 이벤트를 여러 번 재생해도 같은 상태
  onOrderCreatedEvent(event: OrderCreatedEvent) {
    this.orderId = event.orderId;
    this.userId = event.userId;
    this.productId = event.productId;
    this.productName = event.productName;
    this.quantity = event.quantity;
    this.price = event.price;              // 항상 같은 값
    this.discountRate = event.discountRate;
    this.totalAmount = event.totalAmount;
    this.finalAmount = event.finalAmount;
    this.status = OrderStatus.CREATED;
  }
}
```

### 2. Event Handler (외부 통합)

#### 규칙
- ✅ **외부 연동 허용**: DB, API, 이메일, 메시징 등 **주요 목적**
- ⚠️ **멱등성 권장**: At-least-once delivery로 인한 중복 처리 고려
- ✅ **비동기 처리**: 메인 플로우 블로킹 없이 독립적 실행

#### 현재 프로젝트 상태
❌ **현재 프로젝트에는 Event Handler가 없습니다!** (EventStore만 있음)

#### 실제 프로덕션 구현 예시

```typescript
// ✅ 재고 감소 Event Handler
@EventsHandler(OrderCompletedEvent)
export class ProductStockHandler implements IEventHandler<OrderCompletedEvent> {
  constructor(
    private readonly productService: ProductService,  // ✅ 외부 서비스 주입 가능!
    private readonly database: Database,               // ✅ DB 연동 가능!
  ) {}

  async handle(event: OrderCompletedEvent) {
    // ⚠️ 멱등성 고려: 같은 이벤트가 2번 전달되면 재고가 2번 감소!

    // ✅ 멱등성 보장 방법 1: 이벤트 처리 이력 확인
    const alreadyProcessed = await this.database.checkEventProcessed(
      event.orderId,
      'ProductStockHandler',
    );

    if (alreadyProcessed) {
      console.log('이미 처리된 이벤트, 스킵');
      return;  // 중복 처리 방지
    }

    // ✅ 외부 DB 연동 - 재고 감소
    await this.productService.decreaseStock(
      event.productId,
      event.quantity,
    );

    // ✅ 처리 완료 기록
    await this.database.markEventProcessed(
      event.orderId,
      'ProductStockHandler',
    );
  }
}

// ✅ 이메일 발송 Event Handler
@EventsHandler(OrderCompletedEvent)
export class EmailNotificationHandler implements IEventHandler<OrderCompletedEvent> {
  constructor(
    private readonly emailService: EmailService,  // ✅ 외부 API 호출 가능
  ) {}

  async handle(event: OrderCompletedEvent) {
    // ✅ 외부 API 연동 - 이메일 발송
    await this.emailService.send({
      to: event.userEmail,
      subject: '주문 완료',
      body: `주문번호 ${event.orderId} 결제 완료`,
    });

    // ⚠️ 이메일은 여러 번 보내도 큰 문제 없음 (멱등성 덜 중요)
    // 하지만 포인트 적립, 재고 감소 등은 멱등성 필수!
  }
}

// ✅ 포인트 적립 Event Handler
@EventsHandler(OrderCompletedEvent)
export class PointRewardHandler implements IEventHandler<OrderCompletedEvent> {
  constructor(
    private readonly pointService: PointService,
  ) {}

  async handle(event: OrderCompletedEvent) {
    // ✅ 멱등성 보장 방법 2: 고유 키로 중복 방지
    try {
      await this.pointService.addPoints({
        userId: event.userId,
        orderId: event.orderId,  // 고유 키로 사용
        points: Math.floor(event.finalAmount * 0.01),  // 1% 적립
      });
    } catch (error) {
      if (error.code === 'DUPLICATE_REWARD') {
        console.log('이미 포인트 적립됨');
        return;  // 중복 적립 방지
      }
      throw error;
    }
  }
}
```

### 3. EventStore (이벤트 저장소)

#### 규칙
- ✅ **DB 연동 필수**: 이벤트 영구 저장이 목적
- ✅ **멱등성 보장**: 같은 이벤트 중복 저장 방지
- ✅ **트랜잭션**: 저장 실패 시 롤백

#### 현재 구현 (메모리 기반)

```typescript
// event-store.service.ts (현재)
@Injectable()
export class EventStoreService {
  // ⚠️ 현재는 메모리 기반 (프로덕션에서는 DB 사용 필수)
  private readonly eventStore = new Map<string, IEvent[]>();

  private saveEvent(event: IEvent) {
    const orderId = this.extractOrderId(event);
    if (!orderId) {
      return;
    }

    // 메모리에 저장
    const events = this.eventStore.get(orderId) || [];
    events.push(event);
    this.eventStore.set(orderId, events);
  }
}
```

#### 실제 프로덕션 구현

```typescript
// ✅ 프로덕션 EventStore
@Injectable()
export class EventStoreService {
  constructor(
    private readonly database: Database,  // ✅ DB 연동 필수
    private readonly eventBus: EventBus,
  ) {}

  async saveEvent(event: IEvent) {
    const orderId = this.extractOrderId(event);

    // ✅ DB에 영구 저장
    await this.database.events.insert({
      eventId: uuid(),                           // 고유 ID
      aggregateId: orderId,                      // 주문 ID
      aggregateType: 'Order',                    // Aggregate 타입
      eventType: event.constructor.name,         // 이벤트 타입
      eventData: JSON.stringify(event),          // 이벤트 데이터
      version: event.version,                    // 이벤트 버전 (순서 보장)
      timestamp: new Date(),
      metadata: {
        userId: event.userId,
        correlationId: event.correlationId,
      },
    });

    // ✅ 멱등성 보장: (aggregateId, version)에 UNIQUE 제약
    // 같은 version의 이벤트가 이미 있으면 저장 실패
  }

  async getEventsByOrderId(orderId: string): Promise<IEvent[]> {
    // ✅ DB에서 조회, version 순으로 정렬
    const rows = await this.database.events.find({
      aggregateId: orderId,
      aggregateType: 'Order',
    }).orderBy('version', 'ASC');

    return rows.map(row => this.deserializeEvent(row));
  }
}
```

#### EventStore 테이블 스키마

```sql
CREATE TABLE events (
  event_id VARCHAR(36) PRIMARY KEY,
  aggregate_id VARCHAR(36) NOT NULL,
  aggregate_type VARCHAR(50) NOT NULL,
  event_type VARCHAR(100) NOT NULL,
  event_data JSON NOT NULL,
  version INT NOT NULL,
  timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  metadata JSON,

  -- ✅ 멱등성 보장: 같은 Aggregate의 같은 version 중복 방지
  UNIQUE KEY unique_version (aggregate_id, version),

  INDEX idx_aggregate (aggregate_id, version)
);
```

## 외부 데이터 조회 시점

### 핵심 원칙
**Command Handler에서 모든 외부 데이터를 조회한 후 Aggregate에 전달!**

### 현재 구현 분석

#### Controller (현재)
```typescript
// order.controller.ts
export class CreateOrderDto {
  userId: string;
  productId: string;
  productName: string;  // ⚠️ 클라이언트가 전송 (조작 가능!)
  quantity: number;
  price: number;        // ⚠️ 클라이언트가 전송 (조작 가능!)
  discountRate: number;
}

@Post()
async createOrder(@Body() dto: CreateOrderDto) {
  // ⚠️ 클라이언트가 보낸 가격을 그대로 사용
  await this.commandBus.execute(
    new CreateOrderCommand(
      orderId,
      dto.userId,
      dto.productId,
      dto.productName,  // 클라이언트 값
      dto.quantity,
      dto.price,        // 클라이언트 값 (위험!)
      dto.discountRate,
    ),
  );
}
```

**문제점**:
- 클라이언트가 가격을 조작할 수 있음! 💥
- 1,000,000원 상품을 100원으로 변조 가능

#### Command Handler (현재)
```typescript
// create-order.handler.ts
@CommandHandler(CreateOrderCommand)
export class CreateOrderHandler {
  constructor(private readonly eventPublisher: EventPublisher) {}

  async execute(command: CreateOrderCommand): Promise<void> {
    const { orderId, userId, productId, productName, quantity, price, discountRate } = command;

    // ❌ 외부 데이터 조회 없음!
    // ❌ 가격 검증 없음!

    const order = this.eventPublisher.mergeObjectContext(
      new OrderAggregate(orderId),
    );

    // Command에서 받은 가격을 그대로 사용
    order.createOrder(userId, productId, productName, quantity, price, discountRate);

    order.commit();
  }
}
```

#### Command Handler (개선)
```typescript
// ✅ 개선된 Command Handler
@CommandHandler(CreateOrderCommand)
export class CreateOrderHandler {
  constructor(
    private readonly eventPublisher: EventPublisher,
    private readonly productService: ProductService,  // 🆕 외부 서비스 주입
    private readonly userService: UserService,        // 🆕 사용자 서비스
    private readonly inventoryService: InventoryService,  // 🆕 재고 서비스
  ) {}

  async execute(command: CreateOrderCommand): Promise<void> {
    const { orderId, userId, productId, quantity, discountRate } = command;

    // 🔍 1. 외부 데이터 조회 (commandBus.execute() 이후, Aggregate 호출 이전)
    const [product, user, inventory] = await Promise.all([
      this.productService.getProduct(productId),
      this.userService.getUser(userId),
      this.inventoryService.checkStock(productId),
    ]);

    // 🔍 2. 데이터 검증
    if (!product) {
      throw new Error(`제품을 찾을 수 없습니다: ${productId}`);
    }
    if (!product.isActive) {
      throw new Error('판매 중지된 제품입니다');
    }

    if (!user) {
      throw new Error(`사용자를 찾을 수 없습니다: ${userId}`);
    }
    if (!user.isActive) {
      throw new Error('비활성화된 사용자입니다');
    }

    // 🔍 3. 비즈니스 규칙 검증 (외부 데이터 기반)
    if (inventory.availableStock < quantity) {
      throw new Error(
        `재고 부족: 현재 ${inventory.availableStock}개, 요청 ${quantity}개`,
      );
    }

    // ✅ 4. Aggregate 생성 (순수 도메인 로직)
    const order = this.eventPublisher.mergeObjectContext(
      new OrderAggregate(orderId),
    );

    // ✅ 5. 도메인 로직 실행 (외부에서 조회한 데이터 전달)
    order.createOrder(
      userId,
      productId,
      product.name,           // 🆕 서버에서 조회한 제품명
      quantity,
      product.currentPrice,   // 🆕 서버에서 조회한 현재 가격 (조작 불가!)
      discountRate,
    );

    // ✅ 6. 이벤트 커밋
    order.commit();
  }
}
```

## 데이터 흐름 비교

### ❌ 잘못된 구조: Aggregate에서 외부 조회

```
Controller
  ↓
commandBus.execute(CreateOrderCommand)
  ↓
Command Handler
  ↓
Aggregate.createOrder()
  ↓
  ❌ const product = await this.productService.getProduct()  // 안 됨!
  ❌ const price = product.currentPrice
  ❌ await this.database.save(order)                         // 안 됨!
  ↓
Event 발행
```

**문제점**:
1. 상태 복원(`getOrderById`) 시 매번 외부 조회 발생 💥
2. 외부 서비스 장애 시 복원 불가 💥
3. 순수 함수가 아니므로 테스트 어려움 💥
4. 멱등성 보장 불가 💥

### ✅ 올바른 구조: Command Handler에서 외부 조회

```
Controller (productId만 전달)
  ↓
commandBus.execute(CreateOrderCommand)
  ↓
Command Handler
  │
  ├─→ 🔍 ProductService.getProduct(productId)     // 외부 조회
  ├─→ 🔍 UserService.getUser(userId)              // 외부 조회
  ├─→ 🔍 InventoryService.checkStock(productId)   // 외부 조회
  │
  ├─→ ✅ 데이터 검증 (product 존재, user 활성화 등)
  ├─→ ✅ 비즈니스 규칙 검증 (재고 충분, 가격 유효 등)
  │
  └─→ Aggregate.createOrder(조회한 모든 데이터)
        ↓
        ✅ 순수 검증 로직 (if quantity <= 0)
        ↓
        ✅ this.apply(new OrderCreatedEvent(...))  // 모든 데이터 포함!
        ↓
      Event 발행 (EventBus)
        ↓
        ├─→ EventStore.saveEvent()
        │     ↓
        │     ✅ DB에 이벤트 저장 (영구 보관)
        │
        └─→ Event Handlers (독립적 실행)
              ├─→ ProductStockHandler (재고 감소)
              ├─→ EmailNotificationHandler (이메일 발송)
              ├─→ PointRewardHandler (포인트 적립)
              └─→ AnalyticsHandler (주문 통계)
```

**장점**:
1. Aggregate는 순수 함수 유지 ✅
2. 상태 복원 시 외부 조회 불필요 ✅
3. 테스트 용이 (Mock 불필요) ✅
4. 멱등성 보장 ✅

## 실전 예시

### 시나리오: 가격 변경 감지 결제

#### 요구사항
```
1일: 주문 생성 (제품 A: 100원)
2일: 판매자가 가격을 200원으로 인상
3일: 결제 시도 → 가격 변경 감지 → 결제 실패
```

#### 구현

```typescript
// 1. Command 수정
export class ProcessPaymentCommand {
  constructor(
    public readonly orderId: string,
    public readonly userBalance: number,
    public readonly verifyPrice?: boolean,  // 🆕 가격 검증 옵션
  ) {}
}

// 2. Command Handler에서 외부 데이터 조회
@CommandHandler(ProcessPaymentCommand)
export class ProcessPaymentHandler {
  constructor(
    private readonly eventPublisher: EventPublisher,
    private readonly eventStore: EventStoreService,
    private readonly productService: ProductService,  // 🆕 제품 서비스
  ) {}

  async execute(command: ProcessPaymentCommand): Promise<void> {
    const { orderId, userBalance, verifyPrice } = command;

    // 1. 상태 복원
    const order = await this.eventStore.getOrderById(orderId);
    if (!order) {
      throw new Error(`주문을 찾을 수 없습니다: ${orderId}`);
    }

    // 🔍 2. 외부 데이터 조회 (가격 검증 옵션인 경우)
    let currentProductPrice: number | undefined;
    if (verifyPrice) {
      const product = await this.productService.getProduct(order.getProductId());
      currentProductPrice = product.currentPrice;
    }

    // 3. EventPublisher로 래핑
    const orderWithPublisher = this.eventPublisher.mergeObjectContext(order);

    // 4. 비즈니스 로직 실행 (현재 가격 전달)
    orderWithPublisher.processPayment(userBalance, currentProductPrice);

    // 5. 이벤트 커밋
    orderWithPublisher.commit();
  }
}

// 3. Aggregate에서 가격 검증 (순수 로직)
export class OrderAggregate extends AggregateRoot {
  processPayment(userBalance: number, currentProductPrice?: number) {
    // 기존 검증...

    // 🆕 가격 변경 검증 (외부에서 받은 데이터 기반)
    if (currentProductPrice !== undefined && this.price !== currentProductPrice) {
      this.apply(
        new PaymentFailedEvent(
          this.orderId,
          this.userId,
          this.finalAmount,
          PaymentFailureReason.PRICE_CHANGED,
          `제품 가격이 변경되었습니다. 주문 시: ${this.price}원, 현재: ${currentProductPrice}원`,
          new Date(),
          {
            orderTimePrice: this.price,
            currentPrice: currentProductPrice,
            priceDifference: currentProductPrice - this.price,
          },
        ),
      );
      return;  // ❌ 결제 실패
    }

    // 기존 결제 로직...
  }
}
```

### ❌ 실수 2: Event Handler 멱등성 미보장

```typescript
// ❌ 잘못된 예시
@EventsHandler(OrderCompletedEvent)
export class PointRewardHandler {
  async handle(event: OrderCompletedEvent) {
    // ❌ 멱등성 보장 없음
    // 같은 이벤트가 2번 전달되면 포인트 2번 적립!
    await this.pointService.addPoints(
      event.userId,
      Math.floor(event.finalAmount * 0.01),
    );
  }
}
```

**문제점**:
- At-least-once delivery로 인해 같은 이벤트가 여러 번 전달될 수 있음
- 포인트가 중복 적립됨 💥

**해결책**:
```typescript
// ✅ 올바른 예시
@EventsHandler(OrderCompletedEvent)
export class PointRewardHandler {
  async handle(event: OrderCompletedEvent) {
    // ✅ 멱등성 보장: 이미 처리했는지 확인
    const alreadyProcessed = await this.database.checkProcessed(
      event.orderId,
      'PointRewardHandler',
    );

    if (alreadyProcessed) {
      return;  // 이미 처리됨
    }

    await this.pointService.addPoints(
      event.userId,
      Math.floor(event.finalAmount * 0.01),
    );

    // ✅ 처리 완료 기록
    await this.database.markProcessed(event.orderId, 'PointRewardHandler');
  }
}
```

### ❌ 실수 3: Controller에서 비즈니스 로직 실행

```typescript
// ❌ 잘못된 예시
@Post()
async createOrder(@Body() dto: CreateOrderDto) {
  // ❌ Controller에서 제품 조회
  const product = await this.productService.getProduct(dto.productId);

  // ❌ Controller에서 재고 검증
  if (product.stock < dto.quantity) {
    throw new Error('재고 부족');
  }

  // ❌ Controller에서 가격 계산
  const finalAmount = product.price * dto.quantity * (1 - dto.discountRate / 100);

  await this.commandBus.execute(
    new CreateOrderCommand(orderId, product.price, finalAmount),
  );
}
```

**문제점**:
- Controller가 비즈니스 로직을 알게 됨 (계층 책임 위반)
- 재사용 불가 (CLI, 메시지 큐 등에서 호출 시 로직 중복)
- 테스트 어려움

**해결책**:
```typescript
// ✅ 올바른 예시
@Post()
async createOrder(@Body() dto: CreateOrderDto) {
  // ✅ Controller는 Command만 전달
  await this.commandBus.execute(
    new CreateOrderCommand(
      orderId,
      dto.userId,
      dto.productId,
      dto.quantity,
      dto.discountRate,
    ),
  );
}

// ✅ Command Handler에서 모든 비즈니스 로직 처리
@CommandHandler(CreateOrderCommand)
export class CreateOrderHandler {
  async execute(command: CreateOrderCommand) {
    // 외부 조회
    const product = await this.productService.getProduct(command.productId);

    // 재고 검증
    if (product.stock < command.quantity) {
      throw new Error('재고 부족');
    }

    // Aggregate에 전달
    order.createOrder(product.price, product.name, command.quantity);
  }
}
```

## 요약

### 계층별 책임

| 계층 | 외부 의존성 | 멱등성 | 주요 역할 |
|------|-------------|--------|-----------|
| **Controller** | ❌ 최소화 | N/A | HTTP 요청 → Command 변환 |
| **Command Handler** | ✅ 허용 (필수!) | N/A | 외부 데이터 조회 + 비즈니스 검증 |
| **Aggregate** | ❌ 절대 금지 | ✅ 필수 | 순수 도메인 로직 + 이벤트 발행 |
| **EventStore** | ✅ DB 연동 필수 | ✅ 필수 | 이벤트 영구 저장 |
| **Event Handler** | ✅ 허용 (주목적) | ⚠️ 권장 | 외부 시스템 통합 |

### 데이터 흐름 원칙

```
Controller (최소 정보)
  ↓
Command Handler
  ├─→ 외부 서비스 조회 (Product, User, Inventory)
  ├─→ 데이터 검증
  ├─→ 비즈니스 규칙 검증
  └─→ Aggregate (조회한 모든 데이터 전달)
        ↓
      순수 도메인 로직
        ↓
      Event 발행
        ↓
      ├─→ EventStore (DB 저장)
      └─→ Event Handlers (외부 통합)
```

### 핵심 원칙

1. **Aggregate는 순수 함수**: 외부 의존성 절대 금지, 멱등성 필수
2. **Command Handler에서 외부 조회**: 모든 필요한 데이터를 준비 후 Aggregate에 전달
3. **Event Handler는 외부 통합**: DB, API 호출 가능하지만 멱등성 고려
4. **EventStore는 진실의 원천**: 모든 이벤트를 영구 저장, 멱등성 보장
