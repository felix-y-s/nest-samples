## 문제 상황

### 시나리오: 재고 감소 실패

```
1일: 사용자 A가 제품 주문 (재고: 10개)
2일: 사용자 A 결제 완료
     → OrderCompletedEvent 발행 ✅
     → EventBus → ProductStockHandler

     동시에 다른 일이 발생:
     - 사용자 B가 같은 제품 9개 구매 (재고: 1개 남음)
     - 또는 판매자가 재고를 5개로 조정

     → ProductStockHandler에서 재고 감소 시도
     → ❌ 재고 부족! (1개 < 요청 5개)

문제: 이미 OrderCompletedEvent는 발행되었고,
     Aggregate 루틴은 끝났는데 어떻게 처리?
```

### 구체적인 흐름

```
1. Order Aggregate
   ↓
   order.processPayment(userBalance)
   ↓
   PaymentSucceededEvent 발행 ✅
   OrderCompletedEvent 발행 ✅ (이미 커밋됨!)
   ↓
2. order.commit()
   ↓ EventBus로 전파

3. Event Handlers (동시 실행)
   ├─→ EventStore: 이벤트 저장 ✅
   ├─→ EmailHandler: 이메일 발송 ✅
   └─→ ProductStockHandler: 재고 감소 시도
         ↓
         ❌ 재고 부족 에러!

⚠️ 이미 OrderCompletedEvent는 EventStore에 저장됨 (불변!)
⚠️ Aggregate 루틴은 이미 종료됨
⚠️ 사용자는 "결제 완료" 이메일을 받은 상태
⚠️ 어떻게 처리해야 하나?
```

---

## 핵심 딜레마

### 왜 어려운가?

1. **이벤트 불변성**
   - OrderCompletedEvent는 이미 EventStore에 저장됨
   - 과거는 바꿀 수 없음 (Event Sourcing의 핵심 원칙)

2. **Aggregate 루틴 종료**
   - `order.commit()`이 이미 완료됨
   - Aggregate는 이미 메모리에서 해제됨

3. **Event Handler 제약**
   - Event Handler는 이벤트를 **직접 발행할 수 없음**
   - 오직 Aggregate만 `this.apply()`로 이벤트 발행 가능

4. **사용자 경험**
   - 사용자는 이미 "결제 완료" 알림을 받음
   - 갑자기 주문이 실패하면 혼란

### 잘못된 시도들

```typescript
// ❌ 잘못된 시도 1: Event Handler에서 이벤트 직접 발행
@EventsHandler(OrderCompletedEvent)
export class ProductStockHandler {
  async handle(event: OrderCompletedEvent) {
    try {
      await this.inventoryService.decreaseStock(event.productId, event.quantity);
    } catch (error) {
      // ❌ 이렇게 할 수 없음!
      this.apply(new StockDecreaseFailed(...));  // apply() 메서드 없음!
    }
  }
}

// ❌ 잘못된 시도 2: 이미 발행된 이벤트를 취소
@EventsHandler(OrderCompletedEvent)
export class ProductStockHandler {
  async handle(event: OrderCompletedEvent) {
    try {
      await this.inventoryService.decreaseStock(event.productId, event.quantity);
    } catch (error) {
      // ❌ 이벤트는 불변! 취소/삭제 불가!
      await this.eventStore.deleteEvent(event);  // 이런 메서드 없음!
    }
  }
}

// ❌ 잘못된 시도 3: 단순 예외 던지기
@EventsHandler(OrderCompletedEvent)
export class ProductStockHandler {
  async handle(event: OrderCompletedEvent) {
    // ❌ 예외만 던지면 끝?
    throw new Error('재고 부족');
    // → 아무도 처리하지 않음, 주문은 "완료" 상태로 남음!
  }
}
```

## 해결 방법 4가지

### Solution 1: 선제적 검증 (Optimistic Locking)

**핵심 아이디어**:
Event Handler 실행 **전**에 재고를 미리 예약/확인하여 문제를 예방합니다.

#### 아키텍처

```
Command Handler (결제 전)
  ↓
  🔍 1. 재고 확인
  🔒 2. 재고 예약 (Lock 획득)
  ↓
  재고 부족?
  ├─ ❌ 예: 결제 실패 (OrderCompletedEvent 발행 안 함)
  └─ ✅ 아니오: 결제 진행
      ↓
      OrderCompletedEvent 발행
      ↓
      Event Handler
      ↓
      ✅ 3. 예약 확정 (실제 재고 감소)
```

#### 구현 코드

```typescript
// ===== 1. Command Handler: 선제적 검증 =====
@CommandHandler(ProcessPaymentCommand)
export class ProcessPaymentHandler {
  constructor(
    private readonly eventPublisher: EventPublisher,
    private readonly eventStore: EventStoreService,
    private readonly inventoryService: InventoryService,  // 🆕 재고 서비스
  ) {}

  async execute(command: ProcessPaymentCommand): Promise<void> {
    const { orderId, userBalance } = command;

    // 1. 상태 복원
    const order = await this.eventStore.getOrderById(orderId);
    if (!order) {
      throw new Error(`주문을 찾을 수 없습니다: ${orderId}`);
    }

    // 2. 주문 정보 추출
    const productId = order.getProductId();
    const quantity = order.getQuantity();

    // 🔍 3. 결제 전에 재고 검증 및 예약
    try {
      // ✅ 재고 예약 (Lock 획득)
      await this.inventoryService.reserveStock(productId, quantity, orderId);
      console.log(`✅ 재고 예약 완료: 제품 ${productId}, ${quantity}개`);
    } catch (InsufficientStockError) {
      // ❌ 재고 부족 - 결제 자체가 실패!
      console.error(`❌ 재고 부족으로 결제 실패: 제품 ${productId}`);
      throw new Error(`재고 부족: 제품 ${productId}, 요청 ${quantity}개`);
    }

    // 4. EventPublisher로 래핑
    const orderWithPublisher = this.eventPublisher.mergeObjectContext(order);

    // 5. 비즈니스 로직 실행
    orderWithPublisher.processPayment(userBalance);

    // 6. 이벤트 커밋
    // → OrderCompletedEvent 발행
    // → ProductStockHandler에서 예약된 재고를 확정 감소
    orderWithPublisher.commit();
  }
}

// ===== 2. InventoryService: 재고 예약 관리 =====
@Injectable()
export class InventoryService {
  constructor(private readonly database: Database) {}

  /**
   * 재고 예약 (Lock 획득)
   */
  async reserveStock(
    productId: string,
    quantity: number,
    orderId: string,
  ): Promise<void> {
    // 재고 조회
    const inventory = await this.database.inventory.findOne({ productId });

    if (!inventory) {
      throw new Error(`제품을 찾을 수 없습니다: ${productId}`);
    }

    // 재고 확인
    if (inventory.availableStock < quantity) {
      throw new InsufficientStockError(
        `재고 부족: 현재 ${inventory.availableStock}개, 요청 ${quantity}개`,
      );
    }

    // ✅ 재고 예약 생성
    await this.database.reservations.insert({
      reservationId: uuid(),
      orderId,
      productId,
      quantity,
      status: 'RESERVED',
      expiresAt: new Date(Date.now() + 10 * 60 * 1000),  // 10분 후 만료
      createdAt: new Date(),
    });

    // ✅ 가용 재고 감소, 예약 재고 증가 (트랜잭션)
    await this.database.inventory.update(
      { productId },
      {
        $inc: {
          availableStock: -quantity,    // 가용 재고 감소
          reservedStock: +quantity,     // 예약 재고 증가
        },
      },
    );

    console.log(`🔒 재고 예약: 제품 ${productId}, ${quantity}개`);
  }

  /**
   * 재고 예약 확정 (실제 감소)
   */
  async confirmReservation(orderId: string): Promise<void> {
    // 예약 조회
    const reservation = await this.database.reservations.findOne({
      orderId,
      status: 'RESERVED',
    });

    if (!reservation) {
      throw new Error(`예약을 찾을 수 없습니다: ${orderId}`);
    }

    // ✅ 예약 상태 → 확정
    await this.database.reservations.update(
      { orderId },
      { status: 'CONFIRMED' },
    );

    // ✅ 예약 재고 → 실제 판매 재고로 전환
    await this.database.inventory.update(
      { productId: reservation.productId },
      {
        $inc: {
          reservedStock: -reservation.quantity,   // 예약 재고 감소
          soldStock: +reservation.quantity,       // 판매 재고 증가
        },
      },
    );

    console.log(`✅ 재고 확정: 주문 ${orderId}`);
  }

  /**
   * 재고 예약 취소
   */
  async cancelReservation(orderId: string): Promise<void> {
    const reservation = await this.database.reservations.findOne({
      orderId,
      status: 'RESERVED',
    });

    if (!reservation) {
      return;  // 이미 취소되었거나 없음
    }

    // 예약 취소
    await this.database.reservations.update(
      { orderId },
      { status: 'CANCELLED' },
    );

    // 재고 복원
    await this.database.inventory.update(
      { productId: reservation.productId },
      {
        $inc: {
          availableStock: +reservation.quantity,    // 가용 재고 복원
          reservedStock: -reservation.quantity,     // 예약 재고 감소
        },
      },
    );

    console.log(`🔓 재고 예약 취소: 주문 ${orderId}`);
  }
}

// ===== 3. Event Handler: 예약 확정 =====
@EventsHandler(OrderCompletedEvent)
export class ProductStockHandler implements IEventHandler<OrderCompletedEvent> {
  constructor(
    private readonly inventoryService: InventoryService,
    private readonly database: Database,
  ) {}

  async handle(event: OrderCompletedEvent) {
    // ✅ 멱등성 보장
    const alreadyProcessed = await this.database.checkEventProcessed(
      event.orderId,
      'ProductStockHandler',
    );

    if (alreadyProcessed) {
      console.log(`이미 처리됨: 주문 ${event.orderId}`);
      return;
    }

    // ✅ 이미 예약된 재고를 확정 감소로 전환
    await this.inventoryService.confirmReservation(event.orderId);

    // 처리 완료 기록
    await this.database.markEventProcessed(
      event.orderId,
      'ProductStockHandler',
    );

    console.log(`✅ 재고 감소 완료: 주문 ${event.orderId}`);
  }
}

// ===== 4. 예약 만료 처리 (Scheduled Job) =====
@Injectable()
export class ReservationCleanupService {
  constructor(private readonly database: Database) {}

  @Cron('*/5 * * * *')  // 5분마다 실행
  async cleanupExpiredReservations() {
    const expiredReservations = await this.database.reservations.find({
      status: 'RESERVED',
      expiresAt: { $lt: new Date() },  // 만료된 예약
    });

    for (const reservation of expiredReservations) {
      // 예약 취소
      await this.database.reservations.update(
        { _id: reservation._id },
        { status: 'EXPIRED' },
      );

      // 재고 복원
      await this.database.inventory.update(
        { productId: reservation.productId },
        {
          $inc: {
            availableStock: +reservation.quantity,
            reservedStock: -reservation.quantity,
          },
        },
      );

      console.log(`⏰ 만료된 예약 정리: ${reservation.orderId}`);
    }
  }
}
```

```sql
-- 재고 테이블
CREATE TABLE inventory (
  product_id VARCHAR(36) PRIMARY KEY,
  total_stock INT NOT NULL,           -- 총 재고
  available_stock INT NOT NULL,       -- 가용 재고 (판매 가능)
  reserved_stock INT NOT NULL,        -- 예약 재고 (Lock 획득)
  sold_stock INT NOT NULL,            -- 판매 완료 재고

  -- 제약: total = available + reserved + sold
  CONSTRAINT check_stock
    CHECK (total_stock = available_stock + reserved_stock + sold_stock)
);

-- 재고 예약 테이블
CREATE TABLE stock_reservations (
  reservation_id VARCHAR(36) PRIMARY KEY,
  order_id VARCHAR(36) UNIQUE NOT NULL,  -- 중복 예약 방지
  product_id VARCHAR(36) NOT NULL,
  quantity INT NOT NULL,
  status ENUM('RESERVED', 'CONFIRMED', 'CANCELLED', 'EXPIRED') NOT NULL,
  expires_at TIMESTAMP NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

  INDEX idx_order (order_id),
  INDEX idx_expires (status, expires_at)
);
```

#### 장점

- ✅ **문제 예방**: OrderCompletedEvent 발행 **전**에 재고 확인
- ✅ **사용자 경험**: 재고 부족 시 아예 결제가 진행되지 않음
- ✅ **데이터 일관성**: 예약 시스템으로 동시성 문제 해결
- ✅ **Event Handler 단순화**: 예약 확정만 수행

#### 단점

- ⚠️ **복잡도 증가**: 예약 관리 시스템 필요
- ⚠️ **만료 처리**: 예약 만료 시 재고 복원 로직 필요
- ⚠️ **DB 부하**: 예약 테이블 추가 관리

### Solution 2: 보상 이벤트 발행 (Compensating Event)

**핵심 아이디어**:
Event Handler 실패 시, **Command를 발행**하여 새로운 보상 이벤트(OrderCancelledEvent)를 생성합니다.

#### 아키텍처

```
OrderCompletedEvent 발행 ✅
  ↓
ProductStockHandler 실행
  ↓
재고 감소 시도
  ├─ ✅ 성공: 끝
  └─ ❌ 실패 (재고 부족)
      ↓
      🔄 CancelOrderCommand 발행
      ↓
      CancelOrderHandler 실행
      ↓
      OrderAggregate.cancelOrder()
      ↓
      OrderCancelledEvent 발행 ✅
      ↓
      PaymentRefundHandler 실행
      ↓
      💰 결제 환불 처리
```

#### 구현 코드

```typescript
// ===== 1. Event Handler: 보상 Command 발행 =====
@EventsHandler(OrderCompletedEvent)
export class ProductStockHandler implements IEventHandler<OrderCompletedEvent> {
  constructor(
    private readonly inventoryService: InventoryService,
    private readonly commandBus: CommandBus,  // 🆕 Command Bus 주입
  ) {}

  async handle(event: OrderCompletedEvent) {
    try {
      // 재고 감소 시도
      await this.inventoryService.decreaseStock(
        event.productId,
        event.quantity,
      );

      console.log(`✅ 재고 감소 성공: 제품 ${event.productId}, ${event.quantity}개`);
    } catch (InsufficientStockError) {
      console.error(`❌ 재고 감소 실패: 제품 ${event.productId}`);

      // 🔄 보상 처리: 주문 취소 Command 발행
      await this.commandBus.execute(
        new CancelOrderCommand(
          event.orderId,
          '재고 부족으로 인한 자동 취소',
        ),
      );

      console.log(`🔄 주문 취소 Command 발행: ${event.orderId}`);
    } catch (error) {
      // 기타 오류 (네트워크 오류 등)
      console.error(`⚠️ 재고 감소 중 오류: ${error.message}`);
      throw error;  // 재시도 가능하도록 예외 전파
    }
  }
}

// ===== 2. CancelOrderCommand =====
export class CancelOrderCommand {
  constructor(
    public readonly orderId: string,
    public readonly reason: string,
  ) {}
}

// ===== 3. CancelOrderHandler =====
@CommandHandler(CancelOrderCommand)
export class CancelOrderHandler implements ICommandHandler<CancelOrderCommand> {
  constructor(
    private readonly eventPublisher: EventPublisher,
    private readonly eventStore: EventStoreService,
  ) {}

  async execute(command: CancelOrderCommand): Promise<void> {
    const { orderId, reason } = command;

    // 1. 상태 복원
    const order = await this.eventStore.getOrderById(orderId);
    if (!order) {
      throw new Error(`주문을 찾을 수 없습니다: ${orderId}`);
    }

    // 2. EventPublisher로 래핑
    const orderWithPublisher = this.eventPublisher.mergeObjectContext(order);

    // 3. 주문 취소
    orderWithPublisher.cancelOrder(reason);

    // 4. 이벤트 커밋 → OrderCancelledEvent 발행
    orderWithPublisher.commit();

    console.log(`✅ 주문 취소 완료: ${orderId}, 사유: ${reason}`);
  }
}

// ===== 4. OrderAggregate: cancelOrder 메서드 수정 =====
export class OrderAggregate extends AggregateRoot {
  /**
   * 주문 취소
   */
  cancelOrder(reason: string) {
    // ✅ 완료된 주문도 취소 가능하게 수정 (보상 트랜잭션)
    if (this.status === OrderStatus.CANCELLED) {
      throw new Error('이미 취소된 주문입니다');
    }

    // ✅ 모든 상태에서 취소 가능
    this.apply(
      new OrderCancelledEvent(
        this.orderId,
        this.userId,
        reason,
        new Date(),
      ),
    );
  }

  onOrderCancelledEvent(event: OrderCancelledEvent) {
    this.status = OrderStatus.CANCELLED;
  }
}

// ===== 5. OrderCancelledEvent 처리: 결제 환불 =====
@EventsHandler(OrderCancelledEvent)
export class PaymentRefundHandler implements IEventHandler<OrderCancelledEvent> {
  constructor(
    private readonly paymentService: PaymentService,
    private readonly emailService: EmailService,
  ) {}

  async handle(event: OrderCancelledEvent) {
    // 💰 결제 환불 처리
    await this.paymentService.refund(event.orderId, event.userId);

    console.log(`💰 결제 환불 완료: 주문 ${event.orderId}`);

    // 📧 고객 알림
    await this.emailService.send({
      to: event.userEmail,
      subject: '주문 취소 안내',
      body: `
        주문이 취소되었습니다.

        주문번호: ${event.orderId}
        취소 사유: ${event.reason}

        결제 금액은 영업일 기준 3-5일 내에 환불됩니다.
      `,
    });

    console.log(`📧 취소 알림 이메일 발송: ${event.userEmail}`);
  }
}

// ===== 6. OrderCancelledEvent 처리: 재고 예약 해제 =====
@EventsHandler(OrderCancelledEvent)
export class StockReservationCancelHandler
  implements IEventHandler<OrderCancelledEvent> {
  constructor(private readonly inventoryService: InventoryService) {}

  async handle(event: OrderCancelledEvent) {
    // 예약이 있었다면 취소
    await this.inventoryService.cancelReservation(event.orderId);
    console.log(`🔓 재고 예약 취소: 주문 ${event.orderId}`);
  }
}
```

#### 이벤트 흐름 상세

```
Timeline:

1️⃣ OrderCompletedEvent 발행
   ├─ orderId: "ORDER-123"
   ├─ productId: "PROD-001"
   ├─ quantity: 5
   └─ timestamp: 2025-01-01 10:00:00

   └─ ProductStockHandler: 재고 감소 시도

   ├─ orderId: "ORDER-123"

4️⃣ CancelOrderHandler → OrderAggregate.cancelOrder()
   ↓
   OrderCancelledEvent 발행
   ├─ orderId: "ORDER-123"
   ├─ reason: "재고 부족으로 인한 자동 취소"
   └─ timestamp: 2025-01-01 10:00:05

5️⃣ EventBus → Event Handlers (동시 실행)
   ├─ EventStore: 저장 완료 ✅
   ├─ PaymentRefundHandler: 결제 환불 ✅
   ├─ EmailHandler: "주문 취소" 이메일 발송 ✅

─────────────────────────────────────────────────────────────
최종 상태:
- EventStore: [OrderCreatedEvent, PaymentSucceededEvent,
               OrderCompletedEvent, OrderCancelledEvent]
- 사용자: "주문 완료" → "주문 취소" 알림 수신
- 결제: 환불 완료
- 재고: 변경 없음 (또는 예약 해제)
```

#### 장점

- ✅ **명확한 이력**: OrderCancelledEvent로 취소 기록 남음
- ✅ **정상적인 흐름**: Command → Aggregate → Event 패턴 유지
- ✅ **감사 추적**: 전체 히스토리 추적 가능 (완료 → 취소)

#### 단점

- ⚠️ **사용자 경험 저하**: "결제 완료" → "주문 취소" 알림
- ⚠️ **비동기 처리**: 보상 처리가 즉시 이루어지지 않을 수 있음
- ⚠️ **이중 알림**: "완료" 이메일 + "취소" 이메일

### Solution 3: Saga Pattern (분산 트랜잭션 조율)

**핵심 아이디어**:
Saga가 여러 단계를 조율하고, 실패 시 보상 트랜잭션을 자동 실행합니다.

#### 아키텍처

```
OrderCompletedEvent 발행
  ↓
OrderSaga 감지
  ↓
Saga 단계 실행
  ├─ Step 1: 재고 감소
  │    ├─ ✅ 성공: Step 2로
  │    └─ ❌ 실패: 보상 시작
  │
  ├─ Step 2: 포인트 적립
  │    ├─ ✅ 성공: 완료
  │    └─ ❌ 실패: 보상 시작
  │
  └─ 보상 트랜잭션
       ├─ Compensate Step 1: 재고 복원
       ├─ Compensate Step 2: 포인트 차감
       └─ 주문 취소 Command 발행
```

#### 구현 코드

```typescript
// ===== 1. OrderSaga =====
import { Injectable } from '@nestjs/common';
import { Saga, ICommand, ofType } from '@nestjs/cqrs';
import { Observable } from 'rxjs';
import { map, mergeMap } from 'rxjs/operators';

@Injectable()
export class OrderSaga {
  constructor(
    private readonly inventoryService: InventoryService,
    private readonly pointService: PointService,
  ) {}

  /**
   * 주문 완료 Saga: 재고 감소 → 포인트 적립
   */
  @Saga()
  orderCompleted = (events$: Observable<any>): Observable<ICommand> => {
    return events$.pipe(
      ofType(OrderCompletedEvent),
      mergeMap(async (event: OrderCompletedEvent) => {
        console.log(`🎯 Saga 시작: 주문 ${event.orderId}`);

        try {
          // ✅ Step 1: 재고 감소
          await this.inventoryService.decreaseStock(
            event.productId,
            event.quantity,
          );
          console.log(`✅ Saga Step 1 완료: 재고 감소`);

          // ✅ Step 2: 포인트 적립
          await this.pointService.addPoints(
            event.userId,
            Math.floor(event.finalAmount * 0.01),  // 1% 적립
          );
          console.log(`✅ Saga Step 2 완료: 포인트 적립`);

          // ✅ 모든 단계 성공 → null 반환 (추가 Command 없음)
          console.log(`✅ Saga 완료: 주문 ${event.orderId}`);
          return null;

        } catch (error) {
          console.error(`❌ Saga 실패: ${error.message}`);

          // ❌ 실패 시 보상 트랜잭션 시작
          // → 보상 Command 발행
          return new CancelOrderCommand(
            event.orderId,
            `Saga 실패: ${error.message}`,
          );
        }
      }),
      // null이 아닌 경우만 Command로 전달
      map(command => command as ICommand),
    );
  };

  /**
   * 주문 취소 Saga: 보상 트랜잭션 (재고 복원, 포인트 차감)
   */
  @Saga()
  orderCancelled = (events$: Observable<any>): Observable<ICommand> => {
    return events$.pipe(
      ofType(OrderCancelledEvent),
      mergeMap(async (event: OrderCancelledEvent) => {
        console.log(`🔄 보상 Saga 시작: 주문 ${event.orderId}`);

        // 보상 트랜잭션 실행
        try {
          // 재고 예약이 있었다면 취소
          await this.inventoryService.cancelReservation(event.orderId);
          console.log(`✅ 보상: 재고 예약 취소`);

          // 포인트 적립이 있었다면 차감
          await this.pointService.deductPoints(
            event.userId,
            event.orderId,
          );
          console.log(`✅ 보상: 포인트 차감`);

        } catch (error) {
          console.error(`⚠️ 보상 실패: ${error.message}`);
          // 보상도 실패하면 DLQ로 이동하거나 관리자 알림
        }

        return null;  // 보상 완료
      }),
    );
  };
}

// ===== 2. Module 등록 =====
@Module({
  imports: [CqrsModule],
  providers: [
    // ... 기존 providers
    OrderSaga,  // 🆕 Saga 추가
  ],
})
export class OrderModule {}
```

### Solution 4: 재시도 + Dead Letter Queue (DLQ)

**핵심 아이디어**:
일시적 실패는 재시도, 영구적 실패는 DLQ로 이동하여 수동 처리합니다.

#### 구현 코드

```typescript
// ===== 1. Event Handler: 재시도 + DLQ =====
@EventsHandler(OrderCompletedEvent)
export class ProductStockHandler implements IEventHandler<OrderCompletedEvent> {
  private readonly MAX_RETRIES = 3;
  private readonly RETRY_DELAY_MS = 1000;

  constructor(
    private readonly inventoryService: InventoryService,
    private readonly deadLetterQueue: DeadLetterQueue,
    private readonly alertService: AlertService,
    private readonly commandBus: CommandBus,
  ) {}

  async handle(event: OrderCompletedEvent) {
    let retries = 0;

    while (retries < this.MAX_RETRIES) {
      try {
        // 재고 감소 시도
        await this.inventoryService.decreaseStock(
          event.productId,
          event.quantity,
        );

        console.log(`✅ 재고 감소 성공 (${retries + 1}번째 시도)`);
        return;  // 성공

      } catch (error) {
        retries++;

        // ===== 에러 유형 분석 =====

        // 1. 재고 부족 (영구적 실패)
        if (error instanceof InsufficientStockError) {
          console.error(`🚨 재고 부족 (영구적 실패)`);
          await this.handlePermanentFailure(event, error);
          return;
        }

        // 2. 네트워크 오류 (일시적 실패, 재시도 가능)
        if (error instanceof NetworkError && retries < this.MAX_RETRIES) {
          console.log(`⚠️ 네트워크 오류, 재시도 중... (${retries}/${this.MAX_RETRIES})`);
          await this.sleep(this.RETRY_DELAY_MS * retries);  // Exponential backoff
          continue;
        }

        // 3. DB 연결 오류 (일시적 실패, 재시도 가능)
        if (error instanceof DatabaseError && retries < this.MAX_RETRIES) {
          console.log(`⚠️ DB 오류, 재시도 중... (${retries}/${this.MAX_RETRIES})`);
          await this.sleep(this.RETRY_DELAY_MS * retries);
          continue;
        }

        // 4. 기타 오류
        if (retries < this.MAX_RETRIES) {
          console.log(`⚠️ 오류 발생, 재시도 중... (${retries}/${this.MAX_RETRIES})`);
          await this.sleep(this.RETRY_DELAY_MS * retries);
          continue;
        }

        // ===== 최대 재시도 횟수 초과 =====
        console.error(`🚨 최대 재시도 횟수 초과 (${this.MAX_RETRIES}회)`);
        await this.handlePermanentFailure(event, error);
        return;
      }
    }
  }

  /**
   * 영구적 실패 처리
   */
  private async handlePermanentFailure(
    event: OrderCompletedEvent,
    error: Error,
  ) {
    // 1️⃣ DLQ에 저장 (수동 처리 대기)
    await this.deadLetterQueue.enqueue({
      eventType: 'OrderCompletedEvent',
      eventId: event.orderId,
      eventData: event,
      error: {
        message: error.message,
        stack: error.stack,
        type: error.constructor.name,
      },
      timestamp: new Date(),
      retryCount: this.MAX_RETRIES,
    });

    console.log(`📮 DLQ 저장: 주문 ${event.orderId}`);

    // 2️⃣ 관리자 알림
    await this.alertService.send({
      level: 'CRITICAL',
      title: '재고 감소 실패',
      message: `주문 ${event.orderId}: ${error.message}`,
      orderId: event.orderId,
      productId: event.productId,
      error: error.message,
    });

    console.log(`🚨 관리자 알림 발송: ${error.message}`);

    // 3️⃣ 보상 처리: 주문 취소 Command 발행
    await this.commandBus.execute(
      new CancelOrderCommand(
        event.orderId,
        `재고 감소 실패: ${error.message}`,
      ),
    );

    console.log(`🔄 주문 취소 Command 발행: ${event.orderId}`);
  }

  /**
   * 재시도 대기
   */
  private sleep(ms: number): Promise<void> {
    return new Promise(resolve => setTimeout(resolve, ms));
  }
}

// ===== 2. Dead Letter Queue Service =====
@Injectable()
export class DeadLetterQueue {
  constructor(private readonly database: Database) {}

  /**
   * DLQ에 실패한 이벤트 저장
   */
  async enqueue(item: {
    eventType: string;
    eventId: string;
    eventData: any;
    error: {
      message: string;
      stack?: string;
      type: string;
    };
    timestamp: Date;
    retryCount: number;
  }): Promise<void> {
    await this.database.deadLetterQueue.insert({
      id: uuid(),
      eventType: item.eventType,
      eventId: item.eventId,
      eventData: JSON.stringify(item.eventData),
      errorMessage: item.error.message,
      errorStack: item.error.stack,
      errorType: item.error.type,
      retryCount: item.retryCount,
      status: 'PENDING',  // PENDING, RESOLVED, FAILED
      createdAt: item.timestamp,
      resolvedAt: null,
    });
  }

  /**
   * DLQ에서 실패한 이벤트 조회
   */
  async getPendingItems(limit = 100) {
    return this.database.deadLetterQueue.find({
      status: 'PENDING',
    }).limit(limit);
  }

  /**
   * DLQ 항목 재처리
   */
  async reprocess(itemId: string): Promise<void> {
    const item = await this.database.deadLetterQueue.findOne({ id: itemId });

    if (!item) {
      throw new Error(`DLQ 항목을 찾을 수 없습니다: ${itemId}`);
    }

    // 이벤트 재발행 (수동 트리거)
    const event = JSON.parse(item.eventData);
    await this.eventBus.publish(event);

    // 상태 업데이트
    await this.database.deadLetterQueue.update(
      { id: itemId },
      {
        status: 'RESOLVED',
        resolvedAt: new Date(),
      },
    );
  }
}

    };
  }
}
```

## 실무 권장 조합

### **Best Practice: 다층 방어 전략**

실무에서는 **여러 솔루션을 조합**하여 사용합니다:

```
┌─────────────────────────────────────────────────┐
│ Layer 1: 선제적 검증 (Command Handler)          │
│ - 재고 예약/확인                                 │
│ - 80% 문제 예방                                  │
└─────────────────────────────────────────────────┘
            ↓ (예약 성공 시)
┌─────────────────────────────────────────────────┐
│ Layer 2: Event Handler (재시도 + 보상)          │
│ - 예약 확정 시도                                 │
│ - 일시적 오류: 재시도 (3회)                      │
│ - 영구적 실패: 보상 Command 발행                 │
│ - 15% 문제 처리                                  │
└─────────────────────────────────────────────────┘
            ↓ (보상 실패 시)
┌─────────────────────────────────────────────────┐
│ Layer 3: DLQ + 관리자 알림                       │
│ - DLQ에 실패 이벤트 저장                         │
│ - 관리자에게 즉시 알림                           │
│ - 수동 개입으로 해결                             │
│ - 5% 처리                                        │
└─────────────────────────────────────────────────┘
```

### 구현 예시

```typescript
// ===== ProcessPaymentHandler: Layer 1 =====
@CommandHandler(ProcessPaymentCommand)
export class ProcessPaymentHandler {
  async execute(command: ProcessPaymentCommand) {
    // 🛡️ Layer 1: 선제적 검증
    await this.inventoryService.reserveStock(productId, quantity, orderId);

    // Aggregate 로직
    order.processPayment(userBalance);
    order.commit();  // → OrderCompletedEvent
  }
}

// ===== ProductStockHandler: Layer 2 =====
@EventsHandler(OrderCompletedEvent)
export class ProductStockHandler {
  async handle(event: OrderCompletedEvent) {
    let retries = 0;

    while (retries < this.MAX_RETRIES) {
      try {
        // 🛡️ Layer 2: 예약 확정 (재시도 포함)
        await this.inventoryService.confirmReservation(event.orderId);
        return;  // 성공
      } catch (error) {
        retries++;

        // 일시적 오류: 재시도
        if (this.isTransientError(error) && retries < this.MAX_RETRIES) {
          await this.sleep(1000 * retries);
          continue;
        }

        // 영구적 실패: 보상 처리
        await this.commandBus.execute(
          new CancelOrderCommand(event.orderId, error.message),
        );

        // 🛡️ Layer 3: DLQ + 알림
        await this.handlePermanentFailure(event, error);
        return;
      }
    }
  }

  private async handlePermanentFailure(event, error) {
    // DLQ 저장
    await this.deadLetterQueue.enqueue({
      eventType: 'OrderCompletedEvent',
      eventData: event,
      error,
    });

    // 관리자 알림
    await this.alertService.send({
      level: 'CRITICAL',
      title: '재고 확정 실패',
      message: `주문 ${event.orderId}: ${error.message}`,
    });
  }
}
```

## 핵심 원칙

### 1. **Event Handler는 이벤트를 직접 발행할 수 없다**

```typescript
// ❌ 불가능
@EventsHandler(OrderCompletedEvent)
export class ProductStockHandler {
  async handle(event: OrderCompletedEvent) {
    // ❌ this.apply() 메서드 없음!
    this.apply(new StockDecreaseFailed(...));
  }
}

// ✅ 가능: Command 발행
@EventsHandler(OrderCompletedEvent)
export class ProductStockHandler {
  async handle(event: OrderCompletedEvent) {
    // ✅ Command Bus를 통해 간접 발행
    await this.commandBus.execute(
      new CancelOrderCommand(event.orderId, '재고 부족'),
    );
  }
}
```

### 2. **보상 흐름: Event → Command → Aggregate → Compensating Event**

```
Event Handler 실패
  ↓
Command 발행 (CancelOrderCommand)
  ↓
Command Handler
  ↓
Aggregate.cancelOrder()
  ↓
보상 이벤트 발행 (OrderCancelledEvent)
  ↓
다른 Event Handlers 실행 (환불, 알림, 재고 복원 등)
```

### 3. **과거는 바꿀 수 없다, 새로운 이벤트로 보상한다**

```
Timeline:
─────────────────────────────────────────────
10:00:00  OrderCreatedEvent ✅
10:00:05  PaymentSucceededEvent ✅
10:00:10  OrderCompletedEvent ✅ (과거, 불변)
            ↓
10:00:15  재고 감소 실패 감지 ❌
            ↓
10:00:20  OrderCancelledEvent ✅ (보상)
10:00:25  PaymentRefundedEvent ✅ (보상)
─────────────────────────────────────────────

EventStore:
[
  OrderCreatedEvent,      // 삭제 불가!
  PaymentSucceededEvent,  // 삭제 불가!
  OrderCompletedEvent,    // 삭제 불가!
  OrderCancelledEvent,    // 🆕 보상 이벤트 추가
  PaymentRefundedEvent,   // 🆕 보상 이벤트 추가
]

최종 상태 (이벤트 재생 결과):
- status: CANCELLED (마지막 이벤트 기준)
- 완전한 이력 보존 (완료 → 취소 과정)
```

### 4. **선제적 예방이 최선이다**

```
예방 비용 < 보상 비용

선제적 검증:
- Command Handler에서 재고 예약
- 비용: 예약 테이블 관리
- 효과: 80% 문제 예방

보상 처리:
- 주문 취소 + 결제 환불 + 이메일 발송
- 비용: 사용자 혼란 + 환불 처리 비용
- 효과: 문제 해결 (하지만 이미 발생 후)
```

### 5. **Eventual Consistency 수용**

```
강한 일관성 (ACID):
- 주문 생성 + 재고 감소 + 결제가 단일 트랜잭션
- 실패 시 전체 롤백
- 분산 시스템에서는 불가능

최종 일관성 (BASE):
- 주문 생성 → 재고 감소 (비동기)
- 일시적 불일치 허용
- 최종적으로는 일관된 상태 도달
  (성공 또는 보상을 통한 취소)
```

## 요약

### 핵심 메시지

**"이미 aggregate 루틴의 마지막"이라는 통찰이 정확합니다!**

OrderCompletedEvent는 이미 발행되어 불변 상태입니다. Event Handler는 이벤트를 직접 발행할 수 없으므로, **Command를 발행**하여 새로운 보상 이벤트(OrderCancelledEvent)를 생성해야 합니다.

### 실무 권장 전략

```
1️⃣ 선제적 검증 (80% 예방)
   Command Handler에서 재고 예약

2️⃣ 보상 처리 (15% 처리)
   Event Handler 실패 → CancelOrderCommand 발행

3️⃣ DLQ + 알림 (5% 수동 개입)
   영구 실패 케이스는 관리자가 직접 처리
```

### 계층 간 흐름

```
Event Handler 실패
  ↓
  ❌ 이벤트 직접 발행 불가!
  ✅ Command 발행 (CancelOrderCommand)
  ↓
Command Handler
  ↓
Aggregate.cancelOrder()
  ↓
  ✅ 보상 이벤트 발행 (OrderCancelledEvent)
  ↓
Event Handlers (환불, 알림, 재고 복원)
```

**이것이 Eventual Consistency와 보상 트랜잭션의 실제 모습입니다!** 💡
